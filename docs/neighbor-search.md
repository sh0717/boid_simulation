# 이웃 탐색: 전수 탐색, Grid, KdTree

[문서 안내](README.md) · [Boids 수식](boids-theory.md) · [성능 측정](performance.md)

Boids의 규칙은 가까운 이웃만 사용하지만, 그 이웃을 찾는 과정에도 비용이 듭니다.
이 프로젝트는 **후보를 찾는 자료구조**와 **정확한 거리·시야각 판정**을 분리합니다.
2026-11-07에 확인한 C++ 구현을 기준으로 알고리즘과 비용을 설명합니다.

## 1. 탐색기가 지키는 계약

```text
현재 위치로 Rebuild
→ QueryCandidates(위치, 인지 반경)
→ 자신 제외
→ 정확한 거리 제곱 검사
→ 최대 이웃 수가 설정된 경우 가까운 순으로 선택
→ 분리 누적
→ 시야각 검사
→ 응집·정렬 누적
```

공통 진입점은 [FNeighborSearch](../native/src/simulation/NeighborSearch.cpp)입니다.
`QueryCandidates`는 `const std::vector<int>&`를 반환합니다.
후보 안에는 자기 자신과 반경 밖 개체가 있을 수 있습니다.

| 조건                    | 의미                                                                           |
| ----------------------- | ------------------------------------------------------------------------------ |
| 누락 없음               | $\|\mathbf{x}_j-\mathbf{x}_i\|<R$인 이웃은 후보에 반드시 들어갑니다.           |
| 중복 없음               | 같은 개체를 두 번 반환해 힘을 중복 누적하지 않습니다.                          |
| 정확 판정은 호출자 책임 | 실제 반경·시야각은 `CollectNeighborhood`가 검사합니다.                         |
| 읽기 수명               | 후보 참조는 다음 조회·재구축 전에 소비합니다. 검색 객체가 저장소를 소유합니다. |
| 위치 불변               | 재구축 이후 해당 스텝의 모든 조회가 끝날 때까지 개체 위치를 바꾸지 않습니다.   |

위치 불변은 공간 인덱스와 정확 거리 필터가 같은 스냅샷을 처리하기 위한 군집 단계의
계약입니다. Grid와 KdTree 자체는 Rebuild 중에만 원본 위치를 읽고 조회에 필요한 값을
소유합니다. 원본 버퍼를 변경·해제해도 기존 인덱스의 후보 순서는 유지되지만, 변경된
위치에 대한 정확한 후보를 얻으려면 다시 구축해야 합니다.

넓게 후보를 반환해도 정확 필터를 통과한 이웃만 힘에 반영하면 됩니다.
반대로 실제 이웃을 후보에서 누락하면 군집 동작이 달라집니다. 이 계약 때문에
탐색 구조 교체가 군집 수식 변경으로 이어지지 않습니다.

이웃 최대 수의 기본값 `0`은 제한 없음입니다. 양수를 설정하면 인지 반경 안의
개체 중 가까운 순으로 선택하며, 거리가 같으면 개체 인덱스가 작은 쪽을 선택합니다.
선택 후 분리·시야각·응집·정렬을 계산하므로 시야 밖 개체도 선택된 이웃에 포함될 수
있습니다. 제한은 후보 탐색을 조기에 중단하지 않으므로 거리 검사 횟수를 제한하지 않습니다.

## 2. 전수 탐색: 비교 기준

`AllPairs`는 재구축 때 `[0, 1, ..., N-1]`을 만들고 모든 조회에서 같은 배열을 반환합니다.
UI의 선택지는 Grid·KdTree이며, 전수 탐색은 검사·벤치마크의 기준으로 사용합니다.

```text
for i in [0, N):
    for j in [0, N):
        if i == j: continue
        거리 검사 후 군집 규칙 적용
```

자신을 제외한 거리 검사 수는 한 스텝당 정확히 $N(N-1)$입니다.
320개면 102,080회, 1,200개면 1,438,800회입니다. 방향이 있는 조회이므로
`i → j`와 `j → i`를 각각 계산하며, 시야각 때문에 두 관계의 결과도 다를 수 있습니다.

후보 배열 초기화는 $O(N)$, 모든 개체의 거리·군집 계산은 $O(N^2)$입니다.
근거는 [NeighborSearch.cpp](../native/src/simulation/NeighborSearch.cpp#L12)입니다.

## 3. Uniform Grid: 공간을 같은 크기의 셀로 나눕니다

### 셀 배치와 연결 배열

축별 월드 반크기를 $H_x,H_y,H_z$, 셀 폭을 $h$라고 하면 셀 개수는
$n_a=\lceil 2H_a/h\rceil$입니다. 위치 성분 $p_a$를 다음 셀 좌표로 바꿉니다.

$$
c_a=\operatorname{clamp}\!\left(\left\lfloor\frac{p_a+H_a}{h}\right\rfloor,0,n_a-1\right)
$$

3차원 셀 좌표는 다음 1차원 인덱스로 펼칩니다.

$$
\operatorname{index}(c_x,c_y,c_z)=c_x+n_x(c_y+n_yc_z)
$$

맵의 각 축 전체 길이는 20~500까지 실행 중 변경할 수 있습니다. 셀 폭은 최소 10이며
[grid-layout.js](../src/simulation/grid-layout.js)가 셀 수의 곱이 8,000 이하인 가장 작은
정수 셀 폭을 선택합니다. 예를 들어 200³ 이하는 기존 폭 10, 500³은 폭 25를 사용합니다.
축별 크기가 다른 맵은 가장 긴 축만 기준으로 일률적으로 확대하지 않고 세 축의 셀 수를 함께 계산합니다.

이 구현은 해시 테이블 대신 직접 주소 배열을 사용합니다. 셀마다 별도 컨테이너를
할당하지 않고 `FirstBirdIndexByCell[cell]`과 `NextBirdIndexByBird[bird]`로 연결합니다.

```text
모든 활성 FirstBirdIndexByCell을 -1로 초기화
for bird in [0, N):
    cell = 위치로 셀 인덱스 계산
    NextBirdIndexByBird[bird] = FirstBirdIndexByCell[cell]
    FirstBirdIndexByCell[cell] = bird
```

같은 셀에 개체 0, 3, 7을 차례로 넣으면 `head → 7 → 3 → 0 → -1`입니다.
셀 내부 순회는 삽입의 역순이고, 셀 순회는 Z → Y → X 중첩 루프입니다.
구현은 [SpatialGrid::Rebuild](../native/src/simulation/SpatialGrid.cpp#L36)에 있습니다.

### 후보 셀과 거리 하한

조회 반경이 $R$이면 셀 탐색 반경은 $k=\lceil R/h\rceil$입니다.
중심 셀에서 각 축으로 $k$칸까지, 최대 $(2k+1)^3$개 셀을 검사합니다.
월드 끝에서는 범위를 잘라냅니다. 기본값 $R=h=10$일 때 최대 27개 셀입니다.
인지 반경이 커지면 27개보다 많은 셀을 검사할 수 있습니다.
축별 구간은 `CalculateQueryCellRange`가 양 끝을 포함하는 `FCellRange`로 반환합니다.
이 헬퍼는 세 축의 동일한 범위 계산을 공유하며 Z → Y → X 조회 순서는 바꾸지 않습니다.

각 셀의 영역과 조회점 사이의 축별 거리 하한 $\ell_x,\ell_y,\ell_z$를 구합니다.

$$
D^2_{\mathrm{cell}}=\ell_x^2+\ell_y^2+\ell_z^2
$$

$D^2_{\mathrm{cell}}\ge R^2$이면 그 셀에는 엄격한 반경 안의 이웃이 없으므로 건너뜁니다.
나머지 셀의 개체는 모두 후보로 내보내고 정확한 개체 거리는 호출자가 검사합니다.
구현은 [QueryCandidates](../native/src/simulation/SpatialGrid.cpp#L60)입니다.

기본 월드 `[-25,25]³`, $h=10$, 조회점 `(0,0,0)`, $R=10$의 예입니다.

| 후보 위치  | 셀 좌표   | 실제 거리 | 판정                                                       |
| ---------- | --------- | --------- | ---------------------------------------------------------- |
| `(2,0,0)`  | `(2,2,2)` | 2         | 후보이며 반경 안입니다.                                    |
| `(14,0,0)` | `(3,2,2)` | 14        | 셀은 가깝지만 개체는 정확 거리 검사에서 제외됩니다.        |
| `(9,9,9)`  | `(3,3,3)` | 약 15.588 | 셀 거리 하한은 약 8.660이므로 후보에 들어간 뒤 제외됩니다. |
| `(20,0,0)` | `(4,2,2)` | 20        | 조회 셀 범위 밖이라 후보에 들어가지 않습니다.              |

### Soft 경계의 끝 셀

Soft 모드에서는 개체가 월드 밖으로 이동할 수 있습니다. 셀 좌표는 여전히 유효 범위로
제한하므로 맵 밖 개체는 첫 번째 또는 마지막 셀에 저장됩니다.
이때 가지치기에서도 끝 셀을 바깥쪽으로 무한히 연장한 영역으로 취급합니다.

예를 들어 X 최댓값이 25일 때 X=30과 X=31의 개체는 마지막 셀에 저장되며,
반경 10으로 서로를 찾을 수 있어야 합니다. 마지막 셀을 `[15,25]`에만 한정해
거리 하한을 계산하면 바깥 조회점의 실제 이웃을 잘못 버릴 수 있습니다.
이 계약은 [CalculateCellAxisDistanceLowerBound](../native/src/simulation/SpatialGrid.cpp#L27)에 있습니다.

### 누락을 방지하는 이유와 비용

반경 안의 개체는 각 축 거리도 $R$보다 작으므로 탐색 셀 범위 안에 있습니다.
셀의 거리 하한은 그 셀에 속한 개체까지의 실제 거리보다 클 수 없습니다.
따라서 위 하한으로 버린 셀에서는 반경 안의 이웃이 나오지 않습니다.
각 개체는 한 셀의 연결 배열에 한 번 들어가므로 후보 중복도 발생하지 않습니다.

활성 셀 수를 $C$, 가지치기 전 조회 셀 범위의 크기를 $B_i$,
반환 후보 수를 $Q_i$라고 하면 다음 상한으로 비용을 설명할 수 있습니다.

- 재구축: $O(C+N)$. 활성 셀 초기화도 포함합니다.
- 한 개체 조회와 후보 처리: $O(B_i+Q_i)$.
- 전체 탐색·군집 단계: $O(C+N+\sum_i(B_i+Q_i))$.
- 밀집으로 대부분이 같은 근처 셀에 모이면 후보 처리 비용이 $O(N^2)$까지 커집니다.

현재 배열 용량은 셀 8,000개·개체 10,000개이며, 일반화한 저장 공간은 $O(C+N)$입니다.
고정 반경·제한된 셀 밀도에서 빠르게 동작할 수 있지만 개체 수만으로 선형 시간을
보장하지는 않습니다. 헤더는 [SpatialGrid.h](../native/src/simulation/SpatialGrid.h)입니다.

## 4. KdTree: 좌표의 중앙값으로 나눕니다

### 구축

깊이에 따라 X → Y → Z 축을 반복합니다. 해당 축의 중앙값을 노드로 두고
작은 쪽과 큰 쪽을 재귀적으로 나눕니다. 좌표가 같으면 개체 ID로 순서를 결정합니다.

```text
Build(first, last, depth):
    if first > last: return empty
    axis = [X, Y, Z][depth % 3]
    mid = floor((first + last) / 2)
    PlaceMedianBirdInSlot(first, last, mid, axis)
    split[mid] = position[bird[mid]][axis]
    left[mid] = Build(first, mid - 1, depth + 1)
    right[mid] = Build(mid + 1, last, depth + 1)
    return mid
```

`PlaceMedianBirdInSlot`은 매번 전체 정렬을 하는 대신 선택 대상이 있는 구간만 다시 분할합니다.
현재 구간의 중앙 인덱스에 있는 개체를 pivot으로 사용합니다.
포인터 노드를 개별 할당하지 않고 인덱스·자식·분할축·분할좌표 배열로 저장합니다.
각 배열의 같은 인덱스가 한 노드의 개체, 왼쪽·오른쪽 자식, 분할 축과 좌표를 나타냅니다.
`BirdIndexByNode`는 노드 번호에서 개체 번호를 찾고 `LeftChildNodeIndexByNode`와
`RightChildNodeIndexByNode`는 자식 노드 번호를 찾습니다. 자식이 없으면 -1입니다.
분할 좌표는 재구축 시 저장하므로 조회는 원본 위치를 참조하지 않습니다.

근거는 [PlaceMedianBirdInSlot](../native/src/simulation/KdTree.cpp#L38)과
[BuildBalancedSubtree](../native/src/simulation/KdTree.cpp#L58)입니다.

### 분할면을 이용한 조회

현재 노드의 분할 좌표가 $s$, 조회점의 해당 축 좌표가 $p$이면 $\delta=p-s$로 둡니다.

| 조건           | 방문할 자식 | 이유                                        |
| -------------- | ----------- | ------------------------------------------- |
| $\delta\le R$  | 왼쪽        | 조회 구가 왼쪽 반공간에 닿을 수 있습니다.   |
| $\delta\ge -R$ | 오른쪽      | 조회 구가 오른쪽 반공간에 닿을 수 있습니다. |
| 두 조건 모두   | 양쪽        | 분할면 양쪽에 이웃이 있을 수 있습니다.      |

예를 들어 X=0 분할면에서 조회 X=6, 반경 4이면 왼쪽을 건너뜁니다.
조회 X=2, 반경 4이면 양쪽을 방문합니다. 면에 닿는 경우도 후보 탐색은 허용하고,
정확 거리의 엄격한 `< R` 판정은 호출자가 수행합니다.

방문한 노드의 개체는 먼저 후보에 추가합니다. 노드 자체의 3차원 거리로 후보를
줄이거나, 서브트리 AABB와 조회 구의 교차를 계산하지 않습니다.
따라서 반환 후보 수와 실제 이웃 수가 다를 수 있습니다.

고정 배열 스택으로 순회하며 왼쪽을 먼저 push하고 오른쪽을 나중에 push합니다.
LIFO이므로 두 자식이 모두 있으면 오른쪽을 먼저 방문합니다.
구현은 [KdTree::QueryCandidates](../native/src/simulation/KdTree.cpp#L87)입니다.

### 누락을 방지하는 이유와 비용

왼쪽 서브트리의 좌표는 분할 좌표 이하입니다. $p-s>R$이면 왼쪽의 모든 점은
그 축에서만 이미 반경보다 멉니다. 오른쪽도 반대로 적용됩니다.
반경 안에 있을 가능성이 남은 분기는 모두 방문하므로 정확 이웃을 누락하지 않습니다.
각 개체가 하나의 노드에 대응하고 각 자식을 한 번 방문하므로 중복도 없습니다.

중앙값으로 자식 크기를 나누기 때문에 트리 높이는 $O(\log N)$입니다.
다만 **트리 높이가 곧 반경 조회 비용은 아닙니다.** 넓은 반경이나 밀집된 분포에서는
여러 분기를 방문합니다. 실제 방문 노드 수를 $V_i$라고 하면 한 조회는 $O(V_i)$이며
최악에는 $O(N)$, 전체 개체 조회는 $O(N^2)$입니다.

중앙값 선택이 각 구간에서 선형에 가깝게 끝나면 구축은 $O(N\log N)$입니다.
현재 pivot 선택에는 최악 선형 선택 알고리즘의 보장이 없으므로 분할이 반복해서
불리해지는 입력에서 구축 비용은 $O(N^2)$까지 커질 수 있습니다.
저장 공간은 $O(N)$이고, 구축 재귀·깊이 우선 조회의 스택은 균형 트리 깊이에 비례합니다.
현재 조회 스택 용량 32는 중앙값으로 구축한 최대 10,000개 노드의 트리 깊이에 충분합니다.

## 5. 같은 규칙을 적용하되 계산 순서를 이해합니다

| 항목         | 전수 탐색                    | Grid                              | KdTree                                |
| ------------ | ---------------------------- | --------------------------------- | ------------------------------------- |
| 후보 순서    | 개체 ID 오름차순             | Z/Y/X 셀 순서, 셀 안은 삽입 역순  | 노드 방문 순서, 양쪽이면 오른쪽 우선  |
| 분포 의존성  | 검사 수는 분포와 무관        | 셀 밀도·반경·월드 크기에 영향받음 | 분할면과 조회 반경·점 분포에 영향받음 |
| 매 스텝 준비 | ID 목록 채우기               | 셀 초기화·개체 등록               | 중앙값 트리 재구축                    |
| 정확 필터    | 동일한 `CollectNeighborhood` | 동일                              | 동일                                  |

이웃 집합이 같아도 덧셈 순서가 다르면 부동소수점 결과가 달라질 수 있습니다.
계산은 double, 위치·속도 저장은 float이므로 탐색 방식 간 검증은 이웃 집합의 일치와
허용 오차를 둔 수치 비교를 구분해야 합니다. 같은 방법의 순서도 성급하게 정렬하거나
바꾸면 기존 궤적과 달라질 수 있습니다.

인지 반경 제곱과 시야각 코사인은 `CreateNeighborhoodQuery`가 명령마다 한 번
계산합니다. N개 개체의 이웃 갱신에서 같은 설정의 코사인을 N번 계산하던 소스 구조를
한 번으로 줄였으며, 명령 사이에 설정 파생 값을 보관하지 않습니다. 후보 검사와 합산의
복잡도는 위와 같고, 이 구조 변경만으로 CPU 실행 시간 개선을 주장하지 않습니다.

| 기존 검사 위치                                     | 확인하는 사례                                                |
| -------------------------------------------------- | ------------------------------------------------------------ |
| [logic.test.js](../tests/unit/logic.test.js)       | 인지 반경·시야각, 독립 전수 이웃 판정, Grid/KdTree 궤적 비교 |
| [core-tests.cpp](../tests/native/core-tests.cpp)   | 후보 누락·중복·순서, 구축 원본 수명 종료, 비대칭 격자, 명령 간 시야각·반경 변경 |
| [boundary.test.js](../tests/unit/boundary.test.js) | 경계 모드와 월드 이탈 동작                                   |

이 표는 검사 코드의 위치를 연결합니다. 이번 문서 작성에서 전체 회귀 검사를 재실행했다는
의미는 아니며, 기존 실행 이력은 [검증 기록](verification.md)을 따릅니다.

## 6. 무엇을 비교해야 하는가

자료구조의 선택은 개체 수뿐 아니라 군집 밀도, 인지 반경, 매 스텝 재구축 비용까지
고려해야 합니다. `neighborChecks`는 후보에 대한 개체 거리 검사 횟수이며 셀 가지치기나
트리 분할 비교 횟수를 포함하지 않습니다. 이 값이 작아도 전체 스텝이 더 빠르다고
단정할 수 없습니다.

비교에는 동일한 초기 시드와 규칙을 사용하고, 재구축을 포함한 전체 CPU 스텝 시간을
측정합니다. 기존 기록과 재현 명령은 [성능 측정](performance.md)에 정리했습니다.
