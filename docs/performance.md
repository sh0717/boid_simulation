# 성능 측정과 결과 읽기

[문서 안내](README.md) · [이웃 탐색 알고리즘](neighbor-search.md)

이 문서는 탐색 방법에 따라 **재구축과 군집 계산을 포함한 전체 CPU 스텝 비용**이
어떻게 달라지는지 비교합니다. 측정 코드는 [benchmark.mjs](../tools/benchmark.mjs)입니다.

## 1. 보존한 측정 기록

아래 표는 기존 로컬 `artifacts/cpp-benchmark.json`을
[공개 문서용 원본 사본](data/cpp-benchmark.snapshot.json)으로 복사한 결과입니다.
문서 정리일은 2026-10-26이며, 이번 작업에서 새로 벤치마크를 실행하지 않았습니다.
원본에는 측정 시각·Git 커밋·소스 해시가 없으므로 현재 소스 버전의 성능 보장이나
리팩토링 전후 개선율의 근거로 사용하지 않습니다.

JSON은 전체 설정을 직렬화하지 않으므로 위 기본값은 현재 도구를 읽는 기준이며,
그 값만으로 과거 실행 당시 모든 설정이 동일했다고 증명할 수는 없습니다.

## 2. 기존 결과

시간 단위는 ms/step입니다. `p95`는 360개 시간을 정렬한 배열의 인덱스
`floor(360 × 0.95) = 342`, 즉 343번째 표본입니다. 평균 거리 검사 수는 반올림한 값입니다.

| 개체 수 | 장면        | 방법     | 평균 ms | p95 ms | 평균 거리 검사 수 |
| ------: | ----------- | -------- | ------: | -----: | ----------------: |
|     320 | free-flight | AllPairs |   0.314 |  0.338 |           102,080 |
|     320 | free-flight | Grid     |   0.199 |  0.227 |            12,581 |
|     320 | free-flight | KdTree   |   0.272 |  0.297 |            18,603 |
|     320 | flocking    | AllPairs |   0.740 |  0.848 |           102,080 |
|     320 | flocking    | Grid     |   0.567 |  0.696 |            57,216 |
|     320 | flocking    | KdTree   |   0.705 |  0.809 |            57,187 |
|   1,200 | free-flight | AllPairs |   4.101 |  5.423 |         1,438,800 |
|   1,200 | free-flight | Grid     |   2.004 |  2.332 |           172,983 |
|   1,200 | free-flight | KdTree   |   2.674 |  3.055 |           182,369 |
|   1,200 | flocking    | AllPairs |   9.540 | 11.069 |         1,438,800 |
|   1,200 | flocking    | Grid     |   6.072 |  7.294 |           620,454 |
|   1,200 | flocking    | KdTree   |   6.703 |  8.265 |           537,276 |

### 이 기록에서 확인할 수 있는 점

이 표의 1,200개체·flocking 조건에서는 KdTree의 거리 검사 수가 Grid보다 적지만,
평균 스텝 시간은 Grid가 더 짧게 기록되어 있습니다.
거리 검사 수만으로 전체 시간의 크기를 판단할 수 없음을 보여주는 사례입니다.

## 3. 지표의 범위

`neighborChecks`는 `CollectNeighborhood`가 자기 자신을 제외한 후보의 정확한 거리
검사를 시도할 때 증가합니다. 실제 인지 이웃 수가 아니며, Grid의 셀 거리 하한 검사와
KdTree의 분할면 비교·트리 구축은 이 횟수에 포함되지 않습니다.
관련 구현은 [BirdFlock.cpp](../native/src/simulation/BirdFlock.cpp#L200)에 있습니다.

| 지표                 | 포함하는 것                                | 별도로 확인할 것                             |
| -------------------- | ------------------------------------------ | -------------------------------------------- |
| `meanMs`, `p95Ms`    | JS bridge와 C++/Wasm의 전체 스텝 경과 시간 | 렌더러·DOM·GPU 완료 시간                     |
| `meanDistanceChecks` | 자기 자신을 제외한 후보 거리 검사          | 셀·트리 처리 비용, 실제 가시 이웃 수         |
| 화면 FPS             | 브라우저 표시 주기의 관측값                | CPU 시뮬레이션 시간과 GPU 렌더링 시간의 분리 |

이 벤치마크는 Node.js에서 시뮬레이션만 실행합니다. 화면 FPS나 GPU 처리량을 측정한
결과로 바꾸어 해석할 수 없습니다. 화면 캡처의 순간 수치도 이 표와 측정 범위가 다릅니다.

각 방법은 같은 시드·규칙으로 별도의 시뮬레이션을 진행합니다. 탐색 순서에 따른
부동소수점 차이로 궤적이 조금씩 달라질 수 있으므로 매 스텝 완전히 같은 위치 배열을
재생하는 탐색 전용 벤치마크와도 구분합니다.

## 4. 재현 절차

저장소 루트에서 실행합니다. Node 의존성 설치 방법은 [루트 README](../README.md)를,
코어 재빌드가 필요한 경우 SDK 설치·빌드는 [cpp-core.md](cpp-core.md)를 따릅니다.

```powershell
npm.cmd ci --ignore-scripts
npm.cmd run check:runtime
npm.cmd run benchmark
```

`check:runtime`이 코어 원본·Wasm 불일치를 보고하면 SDK 설치 후
`npm.cmd run build:core`로 코어를 재생성하고 다시 검사합니다. `benchmark`는 콘솔과
`artifacts/cpp-benchmark.json`에 결과를 쓰며 기존 로컬 결과를 덮어씁니다.
공개 문서의 `docs/data/cpp-benchmark.snapshot.json`은 자동으로 바뀌지 않습니다.

새 결과를 공개할 때는 다음을 함께 기록합니다.

1. 실행 날짜, Git 커밋 또는 소스 해시, 코어·Node 버전, CPU·OS.
2. 전체 설정과 월드·장애물 구성, 시드, 워밍업·표본 수.
3. 각 방법의 평균·p95·거리 검사 수와 원본 JSON.
4. 독립 반복 실행의 편차와 측정 범위.

현재 도구는 고정된 순서로 각 조건을 한 번씩 실행하며 반복 실행 간 편차를 출력하지
않습니다. 최적화 효과를 주장하려면 비교 대상 모두를 같은 환경에서 재측정하고,
실행 순서·백그라운드 부하·워밍업의 영향도 함께 확인해야 합니다.
